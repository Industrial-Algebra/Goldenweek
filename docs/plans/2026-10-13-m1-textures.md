# M1 — Textures & Sampled Images (contract)

**Date:** 2026-10-13 · **Branch:** `feat/m1-textures` · **Status:** proposed
**Roadmap:** M1 — the keystone; serves glyph atlases (Miriami's delegation),
image DrawOps, and is the prerequisite for M2 (compute-written textures).
Landing M1 also gives Zunesha ADR 0005 Phase 2 its graphics-consumer rationale.

## Scope

Immutable textures: create-and-upload in one call, sampled as
combined image sampler (set 0, binding 0). No runtime mutation
(glyph atlases are rebuilt, not updated — Miriami's model), no
mipmaps, no arrays, no sRGB in v0.1.

## API (GraphicsBackend)

```rust
pub struct TextureDesc {
    pub width: u32,
    pub height: u32,
}

pub enum FilterMode { Nearest, Linear }

fn create_texture(&self, desc: &TextureDesc, data: &[u8], filter: FilterMode)
    -> Result<Texture>;

fn draw_textured(&self, frame: &mut Frame, pipeline: &RenderPipeline,
    vertices: &GpuBuffer, vertex_count: u32, texture: &Texture) -> Result<()>;
```

- `data` is tightly-packed RGBA8 (`len == w * h * 4`), row-major,
  top-left origin. Format fixed `R8G8B8A8_UNORM` (v0.1).
- `Texture` is an opaque handle (destroy-on-drop, like `GpuBuffer`).
- Vertex layout for textured draws is user WGSL's business: the
  existing `VertexLayout` carries an f32x2 UV at whatever location
  the shader declares. No crate-side `TexturedVertex` type — callers
  define their own (keeps the vertex story uniform).

## Binding model (one decision)

**Every** render pipeline layout declares set 0 / binding 0 =
combined image sampler. Shaders that don't declare it simply don't
reference the set (legal — unbound-and-unreferenced is valid at draw);
`draw_textured` binds it. One layout shape, no per-pipeline texture
config knob, no shader-uses-but-layout-lacks-it footgun.

## Vulkan implementation

- `VkImage` + dedicated `VkDeviceMemory` (memory-type query via the
  borrowed zunesha device's physical device), `VkImageView`,
  `VkSampler` (filter from `FilterMode`; clamp-to-edge, unnormalized
  NO — normalized coords, mip 0 only).
- Upload: hand-rolled host-visible staging buffer (TRANSIENT internal
  detail, not a compute-shared seam — the zunesha::Buffer zero-copy
  line stays for vertex/uniform/compute buffers), one-shot command
  buffer from a dedicated transient pool + own small fence, barriers
  `UNDEFINED → TRANSFER_DST_OPTIMAL → SHADER_READ_ONLY_OPTIMAL`,
  synchronous submit-and-wait at creation. Frame command buffers are
  untouched.
- Drop: destroy image, memory, view, sampler (null-safe).
- Stub backend: both methods → `GraphicsError::NoBackend`.

## Errors

New `GraphicsError` variants: `TextureCreate` (image alloc/map/view/
sampler failures), `TextureUpload` (staging/copy/submit). Zero-extent
and `len != w*h*4` rejected up front as `InvalidArgument`.

## Verification (the M1 proof, triangle-grade)

1. **Unit:** desc validation (zero extent, bad stride).
2. **Hardware:** upload a 2×2 texture with four distinct texels,
   nearest filter, fullscreen quad with quadrant UVs; `read_pixels`
   asserts each quadrant's center pixel equals its texel
   (channel-order-aware BGRA assert, exact — nearest UNORM, no
   blending). A deliberately-shuffled assert must fail (mutation
   guard).
3. **Both-config gates:** clippy/doc `-D warnings`, fmt, 25 existing
   + new tests, triangle example unregressed, validation layers:
   documented 00067 baseline only.
4. `examples/textured.rs`: sampled 2×2 texture → visible readback.

## Out of scope (recorded, not lost)

Mipmaps/sRGB (v0.1), texture update-in-place (M2 conversation —
compute-written textures go through the ADR 0005 Phase 2 ledger),
bindless/descriptor indexing (M3+), y-flip conventions beyond the
verified quadrant test (documented as UNDEFINED for now, pinned by
the test).
